# ラベル対応の判断記録

CSJ分節ラベル・jsut-label・MFA日本語音素セットの対応で、判断が分かれた項目とその理由をここに記録する。`csj_mfa_map.tsv` / `jsut_mfa_map.tsv` の各行がここでの決定に対応するようにする。

## 記録フォーマット

```
### 〔項目名：例 長音の分割方針〕
- 論点:
- 採用した基準:
- 感度分析の対象になるか（YES/NOの場合は理由）:
- 影響を受けるRQ:
```

## 等分割境界の判定方法（2026-07-20 確定。長音・撥音・無声化の⚠3件を一括で解消）

長音・促音・撥音・無声化の各項目に残っていた「XML Phone層の内部境界が等分割の人工物か
実測かをどう判別するか」という共通の未確定事項を、**実データの突合で確定させた。**

- **検証方法**: CSJ配布のTextGrid `seg` tier（分節音ラベルの**原形**。融合ラベル
  `Q,t`・`N,m`・`s,U` がカンマ区切りのまま1区間で入っている）と、XML Phone層
  （segment.pdf §7 の手順で等分割済み）を突合した。**TextGridの1区間に対しXMLが複数Phoneを
  持つ場合、その内部境界は定義上すべて等分割の人工物**であり、フラグの意味を推測せずに
  判定できる。実装は `src/convert/verify_equal_division.py`。
- **検証結果**（先頭3講演・seg 29,549区間）:

  | seg 1区間 → Phone | 件数 | 割合 |
  |---|---|---|
  | 1個（1:1、両端が実測） | 25,248 | 85.44% |
  | 2個 | 4,187 | 14.17% |
  | 3個 | 103 | 0.35% |
  | 4個以上 | 11 | 0.04% |

  融合パターンは事前の予測と一致した（`oH/eH/uH/aH/iH → 2` 長音、`sj,I`・`s,U`・`hj,I → 2`
  無声化融合、`N,n → 2` 撥音融合、`SclS,g`・`SclS,d`・`SclS,b → 2` 有声破裂音）。

- **採用した判定条件**:

      内部境界が等分割由来 ⟺ 不確実フラグが立っている OR いずれかのPhoneが長さ0

  この条件の**感度・特異度はともに100%**である。内訳:

  | 内部境界 | フラグ有 | フラグ無 | 感度 |
  |---|---|---|---|
  | 長さ0を含まない | 4,096 | 0 | **100.00%** |
  | 長さ0を含む | 0 | 331 | 0%（長さ0で判定） |
  | 実測境界（1:1） | 0 | 25,248 | 特異度 **100.00%** |

  当初フラグ単独では感度92.52%で不足と見えたが、取りこぼし331件は**すべて長さ0のPhone**
  （VOT実質ゼロの `SclS`）であり、長さ0を併用すれば完全に識別できる。
- **結論**: **TextGrid `seg` tier との突合を本番パイプラインに組み込む必要はない。**
  XMLの属性（`StartTimeUncertain` / `EndTimeUncertain` と時刻）だけで判定できる。
  `verify_equal_division.py` は検証用として残し、データ更新時の再確認に使う。
- **影響を受けるRQ**: RQ0〜RQ5（境界の評価対象判定は全RQの土台）。

## 実データで判明した符号化上の注意（2026-07-20）

- **補助ラベルは山括弧ではなく `S…S` で符号化されている。** CSJ XML の `PhoneEntity` は
  `<cl>` ではなく **`SclS`**。`PhoneClass` はすべて `others`。実測頻度（先頭3講演）:
  `SclS` 5,604 / `SpzS` 593 / `SsvS` 356 / `S?S` 91 / `SuvS` 60 / `SfvS` 23 / `SbS` 23 /
  `SNS` 12 / `SfrS` 1。`csj_mfa_map.tsv` は当初 `<cl>` で書いており1件も照合しなかったため修正済み。
- **長さ0のPhoneが存在する（全体の0.97%、すべて `SclS`）。** segment.pdf §5.2 の
  「無声破裂音であってもVOTが実際上ゼロになることがある。その場合、`<cl>` と子音ラベルは
  融合ラベルとなって同一の時刻に付与されている」に該当する**仕様どおりの挙動**であり、
  バグではない。`schema.Unit.zero_vot` 属性で保持し、`validate()` は
  `zero_vot=True` の場合のみ長さ0を許容する。**RQ3のVOT分析では「VOT=0」の実測値として
  意味を持つため除外しない。**

## 確定済み項目

### 長音の分割方針（2026-07-20 確定）

- **論点**: 長母音を1分節として扱うか2分節として扱うか。三者の規約が食い違う。
  - japanese_mfa: `aː eː iː oː ɯː ɨː`（IPA長音記号 U+02D0）— **1分節**
  - CSJ 分節音ラベル（.seg）: `aH iH uH eH oH` — **1分節**
  - CSJ Phone（XML）: `a` \| `H` — **2分節、内部境界は等分割**
  - jsut-label: `e e`（母音反復）— **2分節、内部境界はJulius自動アラインメント由来**
- **採用した基準**: **長母音は全コーパスで1分節として扱い、評価対象境界はonsetとoffsetのみとする。** 参照側の内部境界は除去して1区間に統合する。統合前の内部境界時刻は `internal_boundary_t` カラムに保持し、感度分析に回す。
- **理由**: 内部境界はCSJ側が等分割の人工物（segment.pdf §7「長母音を分割する。この場合も等分割する」）、jsut側が自動アラインメント由来であり、**いずれにも人手の音響判断が入っていない**。統合しないとMFAの1分節に対し参照側が2分節となり、長母音のたびに偽の `omission` が計上される。逆にMFA側を等分割して2分節に揃える案（選択肢B）は、両側の内部境界がともに人工物となり、誤差分布の0付近に人工的なスパイクを生んで許容内率を不当に押し上げるため棄却した。
- **付随する決定**:
  1. **`ɯː`/`ɨː` のマージ**: MFAは/u/を後続環境で `ɯ`（既定）と `ɨ`（歯茎・口蓋（化）子音の後）に分けており長音も2系列だが、CSJの `uH` は1系列。**MFA側の2系列を `uH` にマージする**（異音差はRQ1の音素クラスでは扱わない）。
  2. **非語彙的延長の分離**: CSJは転記の `<H>`（非語彙的な母音の延長）が付いた要素にも分節音ラベルとしては短母音を与える（segment.pdf §5.3）。MFA辞書も語彙的長音のみ `ː` を持つため**ラベル同士は整合する**が、音響的に長い区間をMFAがどこで切るかは短母音と挙動が異なりうる。XMLの `Mora/@TagVLong` で層別し、主分析からは除外する。
  3. **MFA辞書の `V V` 表記揺れ**: 辞書内に長音が `ː` にならず母音2個で書かれる項目が実在する（`お姉さん o n e e s a ɴ` と `おねえさん o n eː s a ɴ` が同一発音で異なる分節）。同一母音連続は全体の約1%だが、大半は形態素境界をまたぐ正当な連続（`あいだをおいて a i d a o o i t e`）や略語の字読みであり、**一括正規化は別の誤りを生む**。`src/convert/audit_vv_entries.py` で語彙リストを事前監査し、該当語を特定・件数報告のうえ除外する。
- **⚠ 未完了（次工程に進む前に必須）**: 統合トリガーを **(a) `Phone/@StartTimeUncertain` によるフラグ判定**とするか **(b) `PhoneEntity == "H"` の直判定**とするかが未確定。`src/convert/verify_phone_time_uncertain.py` を **CSJ本番XMLに対して実行し、判定結果（a/bのどちらが確定したか）を本項目に追記すること。** 合成サンプルでの動作確認は済んでいるが本番判定は未実施。**これは長音の分割方針全体の実装ロジックを左右するため、未記載のまま次の工程（誤差算出の実装）に進まない。**
- **感度分析の対象になるか**: **YES。** 保持した `internal_boundary_t` を使い、(a) 統合方式（本決定）と (b) 内部境界を評価対象から除外しつつ2分節を保持する方式で、許容内率と誤差分布が実質的に変わらないことを確認する。両者は理論上同値だが、実装バグの検出に有効。
- **影響を受けるRQ**: RQ0・RQ1・RQ3（長母音の境界が直接入る）。RQ2は局所話速の分母となるモーラ数に影響（`H` を1モーラと数えるか）。**RQ4はCSJ上でのJulius対MFA比較に再定義されたため本決定が適用される**。JSUTは評価対象外となったため（`docs/decisions-log.md` A節 2026-07-20）、jsut側の `e e` 統合は**公開実行例の整合性のためにのみ実施**し、誤差算出には用いない。

### 促音の閉鎖区間の帰属（2026-07-20 確定）

- **論点**: 促音のセグメント構成が三者で **1 : 3 : 2** とずれる。長音（1:1:2）よりずれが大きい。
  - japanese_mfa: `tː`（長さ記号つき単一子音）— **1分節**。**閉鎖専用音素が音素セットに存在しない**
  - CSJ 分節音（.seg）: `<cl>` … `Q,t`（融合ラベル）— 2ラベル
  - CSJ Phone（XML）: `Q` \| `<cl>` \| `t` — **3分節**
  - jsut-label: `cl` \| `t` — 2分節
- **CSJ側の各境界の出所**（segment.pdf §4.1・§4.2・§5.2・§7より）:

  | 境界 | 出所 | 価値 |
  |---|---|---|
  | 閉鎖区間の始端（先行母音の終端） | **実測（人手）** | MFAの `tː` onsetと対応 |
  | `Q` \| `<cl>` の内部境界 | **等分割の人工物**（§7 手順1でQを`<cl>`の前に移動して融合、手順2で等分割） | なし |
  | `<cl>` の終端＝**バースト** | **実測（人手）** | **閉鎖区間長とVOTの分割点** |
  | `t` の終端（声帯振動開始） | **実測（人手）** | MFAの `tː` offsetと対応 |

- **採用した基準**: **選択肢A** — `Q` と `<cl>` を統合して閉鎖区間1単位とし（等分割の人工物を除去）、**バースト境界と `t` は保持する**。MFAとの対応は外側2境界（閉鎖始端・`t`終端）のみで取る。バースト境界はMFA側に対応物が存在しないため**4類型分類から除外**し、`burst_t` カラムに保持してRQ3で用いる。
- **理由**: 長音の決定と同じ論理（人工物は捨て、実測は残す）。バースト境界を `omission` として計上するのは**規約差であってMFAの誤りではない**ため誤り。MFA側を等分割して3分節に揃える案は、長音の選択肢Bと同じ理由（人工物同士の比較が誤差分布に無意味なスパイクを作る）で棄却。促音を丸ごと分析から外す案は、促音が頻出かつMFAが閉鎖を独立モデル化しないため誤差が大きく出やすい興味深い対象であり、損失が大きいため棄却。
- **付随する決定**:
  1. **破裂音促音と摩擦音促音を別クラスとする。** segment.pdf §4.2により、後続子音が摩擦音の場合は `<cl>` を付けず摩擦ノイズの終端に `Q,s` の融合ラベルのみを付ける。構造が異なる（3分節 vs 融合1分節）ため同一 `geminate` クラスにまとめられない。摩擦音促音は内部境界を持たず、Phone層では等分割されるので選択肢Aがそのまま適用できる。
  2. **転記タグF/D末尾の融合促音は分析から除外する。** §4.2但し書きにより「(F アッ」「(D コッ」等では `a.Q`・`o.Q` のように促音と先行母音が融合され、**先行母音の境界自体が失われる**。フィラーは自発話に頻出するため、**除外件数を必ず記録**すること。
  3. **VOTの計測制約を記録する。** §5.2により、(i) VOTが実質ゼロの場合 `<cl>` と子音ラベルが融合して同一時刻になる、(ii) 有声破裂音では閉鎖区間中の声帯振動開始点にラベルがないため**負のVOTは計測できない**、(iii) 軟口蓋破裂音でバーストが複数回生じる場合は振幅最大のものに付与される。
- **⚠ 未完了（実装前に必須）**: Phone層での `<cl>` の記法（`PhoneEntity` の属性値、`PhoneClass` の値）が xml.pdf 表1に値一覧がなく確定できない。`src/convert/verify_phone_time_uncertain.py` の PhoneEntity×PhoneClass クロス集計を**CSJ本番XMLに対して実行し、実際の値を本項目に追記すること。** 合成サンプルでは `PhoneEntity="&lt;cl&gt;"` / `PhoneClass="Consonant"` を仮定している。
- **感度分析の対象になるか**: **YES。** 閉鎖区間を統合する方式と、`Q`・`<cl>` を分けたまま内部境界を評価から除外する方式で、許容内率が変わらないことを確認する。
- **影響を受けるRQ**:
  - RQ1 — 促音を音素クラスに含める（破裂音促音／摩擦音促音を分離、F/D末尾融合は除外）。
  - RQ2 — 影響なし。
  - **RQ3 — 拡張部分の設計変更が必要**（`docs/decisions-log.md` A節「RQ3拡張の再定義」を参照）。MFAが閉鎖専用音素を持たないため、MFA出力からVOT・閉鎖区間長を導出できない。
  - RQ4 — jsut-labelは `cl` を独立分節として持ち、その `cl`\|`t` 境界はCSJの `<cl>` 終端と意味的に一致する。**この点ではJuliusのほうがMFAよりCSJの規約に近い**ため、構造的差異として論じられる。
  - RQ5 — 促音は修正コストの高いクラスになる可能性が高く、コスト対効果曲線に効く。

### 撥音の異音統合（2026-07-20 確定）

- **論点**: MFAは撥音を後続環境で6種に分岐させるが、CSJ・jsut-labelはいずれも `N` 一種。また鼻音後続時の融合の扱いが三者で異なる。
  - japanese_mfa: `ɴ`（語末・ポーズ前）/ `m`（両唇音前）/ `n`（歯茎音前）/ `ŋ`（軟口蓋音前）/ `ɲ`（口蓋（化）音前）/ `ɰ̃`（母音・摩擦音・接近音前）。**鼻音の前では後続鼻音と融合して `mː` / `nː`**
  - CSJ 分節音（.seg）: `N` 一種。鼻音後続時は `N,m` / `N,n` の融合ラベル（segment.pdf §4.2・§5.1）
  - CSJ Phone（XML）: `N` \| `m`（融合ラベルを§7手順2で等分割）
  - jsut-label: `N` 一種
  - 辞書実測頻度: `ɴ` 57,106 / `ɲ` 45,242 / `ɰ̃` 36,019 / `ŋ` 27,374 / `nː` 4,064 / `mː` 3,661 / `ɴː` 5
- **採用した基準**: **選択肢A** — 鼻音融合の `N`\|`m` を統合してMFAの `mː` と外側2境界で対応させる。**異音は `N` の1クラスに統合し、後続環境を独立した因子としてRQ1のモデルに投入する**（CSJ側に異音ラベルが存在しないため異音自体はクラスにできないが、後続環境は後続セグメントから導出でき、CSJのラベルに依存しない）。
- **⚠ 撥音固有の問題1：内部境界に実測と人工物が混在する。** segment.pdf §4.2は、鼻音後続時は多くの場合融合するとしたうえで、**稀に語境界があり音声信号に明らかな不連続性（振幅差・フォルマントの異同）が認められる場合は撥音と鼻音を分離してラベリングする**と規定している。したがって `N`\|`m` の内部境界は、融合→等分割なら人工物、分離ラベリングなら実測であり、**値だけでは区別できない**。長音（常に人工物）・促音（`Q`\|`<cl>` は常に人工物）と異なり両方が混在する。
  - **分岐条件**: `StartTimeUncertain` の本番検証で仮説(a)が確定すれば、フラグで機械判定する。**判定不能な場合は、鼻音後続の撥音を感度分析で別扱いにする**（主分析から外し、含めた場合との差を報告する）。
  - あわせて**分離ラベリングの実際の頻度**を推定すること（`N` と鼻音が別Phoneかつ内部境界に不確実フラグが立たない件数）。§4.2は「稀に」としか書いておらず件数が不明。
- **⚠ 撥音固有の問題2：MFAの撥音記号がオンセット子音と重複する。** `簡単 k a n t a ɴ` の `n` は撥音、`なに n a n i` の `n` はオンセット子音で、**MFA出力の記号だけでは区別できない**（`m` も同様: `全部 dz e m b ɯ`）。CSJは撥音を必ず `N` と書くため、記号の単純対応では突き合わせが破綻する。
  - **対処**: 記号ではなく**系列アラインメント＋MFA出力の単語層から辞書エントリを辿る**方式で解決する。MFAのTextGridは単語層を持つため、どの `n` がどの辞書エントリのどの位置に由来するかを追跡できる。
  - **実装先**: **`src/evaluate/sequence_align.py`**（新規、`# SCOPE: shared`）。MFA出力と参照ラベルの系列アラインメントを担い、記号衝突の解消（撥音とオンセット子音の判別）を含む。`src/evaluate/error_types.py` の4類型分類はこのモジュールの出力を入力として受け取る。
- **感度分析の対象になるか**: **YES。**（1）鼻音融合の内部境界を機械判定できない場合の別扱い、（2）後続環境因子を入れた場合と入れない場合の比較。
- **影響を受けるRQ**:
  - RQ1 — 撥音を1クラス＋後続環境因子。`ɰ̃` 環境（母音・摩擦音前）は鼻音化接近音で明確な境界を持たず、CSJ側も §4.2 が「アンチ・フォルマントなどによって鼻音の区間を決定できる場合は」と条件つきで書いており決定できない場合を含意している。**誤差最大のクラスになると事前予測できる。** 音素クラス×後続環境の交互作用を見る価値がある。
  - RQ2 — 影響なし。
  - **RQ3 — 後続環境による層別が必要（モデル実装時に反映すること）。** 撥音に先行する母音の長さ測定に影響する（撥音の onset が母音の offset）。特に `ɰ̃` 環境では母音との境界が不明瞭なため、母音長の誤差が撥音環境で系統的に大きくなる可能性がある。**ICPhS版の母音長分析にも効く**ため、後続環境を共変量に入れるか層別する。
  - RQ4 — jsut-label・Juliusはいずれも `N` 一種で異音を持たない。**この点ではMFAだけが異音を区別する**ため、促音（Juliusのほうが `cl` を持ちCSJに近い）とは逆方向の構造的差異になる。両方向の差異を並べられる。
  - RQ5 — 撥音は頻度が高く（`ɴ` のみで57,106件）、修正効率の観点で優先度が高いクラスになりうる。

### VV表記揺れの `exclude` カテゴリ（2026-07-20 追加）

- **論点**: `results/vv_audit_uncertain.tsv` の残差を検査した結果、merge（長音の表記揺れ）でも keep（形態素境界をまたぐ正当な母音連続）でもない**第3のカテゴリ＝辞書のエラー**が存在することが判明した。
- **採用した基準**: `decision` 列に **`exclude`（辞書エラー。長音でも形態素境界でもなく、辞書の記述そのものが誤り）** を正式なカテゴリとして追加する。該当トークンは分析から除外し、件数を記録する。
- **確認済みの実例**:

  | 表記 | 辞書の音素列 | 問題 |
  |---|---|---|
  | カムチャッカ | `k a m ɯ tɕ a a kː a` | 正しくは `tɕ a kː a`。`a` が1つ余分 |
  | きゃあきゃあ | `c a a c i aː` | 同一語の前半（`c a a`）と後半（`c i aː`）で表記が不一致 |
  | ごせんえんさつ | `ɡ o s e e ɰ̃ s a ts ɨ` | 撥音の扱いが不整合（せんえん → `s e ɰ̃ e ɴ` が期待される） |

- **感度分析の対象になるか**: NO。辞書エラーは統合方針の選択肢ではなく単なる欠損であり、除外以外の扱いがない。ただし**除外件数は必ず報告する**（除外がサンプルに偏りを生んでいないかの確認のため）。
- **影響を受けるRQ**: RQ0〜RQ5すべて（語彙フィルタ層）。ただし実際の影響は、CSJ評価対象語彙との積集合を取った後の件数に依存する（`src/convert/intersect_vv_with_corpus.py`）。

### 無声化母音の脱落分類（2026-07-20 確定）

- **論点**: MFAが無声化母音を「脱落」として出力した場合、omission と substitution のどちらに分類するか。
- **前提となる事実（辞書実物より）**: **japanese_mfa は無声化を3通りに符号化しており、主たる扱いは「母音の削除」である。**

  | 扱い | 例 | 規模 |
  |---|---|---|
  | (1) 無声化音素 `i̥` `ɨ̥` `ɯ̥` | `人 ç i̥ t o`、`洗濯機 s e n t a k ɯ̥ c i` | **合計3,847トークン**のみ |
  | (2) 母音の完全削除 | `した ɕ t a`(0.99) / `ɕ i t a`(0.01)、`靴 k ts ɨ`(0.99)、`少し s k o ɕ i`(0.99) | **多くの語で最高確率の既定形** |
  | (3) 有声のまま | `ɕ i t a`、`k ɯ ts ɨ` | — |

  無声化音素の頻度は `ɴ` の57,106件と比べ2桁小さい。`です` に至っては6変種
  （`d e s ɨ̥` / `d e s` / `d e s ɨ` / `sː ɨ̥` / `sː` / `sː ɨ`）を持つ。
  対象母音も非対称で、MFAは**高母音3種のみ**、CSJは**5母音すべて**（`A I U E O`）を無声化として記録する。
- **採用した基準（選択肢A）**: 融合モーラを**1単位**として扱い、MFA側も対応区間を1区間に統合して**外側2境界のみで対応**させる。内部境界は**参照側に真値が存在しない**ため評価から除外する。
- **理由**: segment.pdf §5.1 は、無声摩擦音を含むモーラに無声化が生じるとモーラ全体が無声摩擦子音として実現され、**「どこまでが子音音素で、どこからが無声化母音であるかを時間軸上で区分することはできない」**と明記し、そのため `sj,I` / `s,U` の融合ラベルを与える（3個以上の融合 `Q,k,U`、`Q,k,U,s,U` も生じる）。**人手ラベラーが決定不可能と宣言した境界**であり、Phone層の等分割値を真値として扱う案（選択肢B）は査読で必ず問題になるため棄却。無声化を丸ごと除外する案（選択肢C）は、無声化が日本語音声学の中心的現象でRQ1の主要対象であるため損失が大きく棄却。
- **付随する決定**:
  1. **omission を属性で下位分類する（5類型目を作らない）。** `omission_provenance` に `lexical`（MFAの選択したバリアントに当該分節が存在しない）/ `alignment`（音素列にはあるが境界が縮退）を持たせる。定義は `src/evaluate/error_types.py` の docstring、5類型目を作らなかった理由は `docs/decisions-log.md` A節を参照。
  2. **substitution に計上しないもの**: (i) MFAが有声形バリアントを選択した場合（`devoiced_voiced_mfa`）、(ii) CSJの非高母音無声化 `A`/`E`/`O`（MFAに対応する無声化音素が存在しない）。いずれもラベル規約の差であってMFAの誤りではないため、写像で吸収する。
  3. **バリアント選択は音響尤度に基づく**ため、lexical omission も純粋な辞書の問題とは言い切れない。この点は論文で明示する。
- **⚠ 未完了（実装前に確認）**: XMLで融合モーラがどう表現されるか（`s` と `U` の両方に `Phone/@Devoiced="1"` が立つのか `U` のみか）が未確認。`verify_phone_time_uncertain.py` のクロス集計に `Devoiced` を含めてあるので本番実行で確認し、本項目に追記すること。
- **感度分析の対象になるか**: **YES。** `omission_provenance` を区別した場合としない場合で、RQ1の音素クラス別 omission 率がどう変わるかを報告する。
- **影響を受けるRQ**:
  - RQ1 — 無声化母音は omission の主要因。来歴の分離が必須。誤差最大級のクラスになる見込み。
  - **RQ2 — 話速と無声化が交絡する。** 話速が上がると無声化・母音削除がともに増えるため、話速の効果と無声化の効果が分離できない。`analysis/rq2_rate_model.R` に無声化有無を共変量候補として検討する旨をコメントで記載済み（実装は後回し）。
  - **RQ3 — ICPhS版に直接影響。** 無声化母音は内部境界に真値がないため**母音長そのものが測定できない**。母音長分析から無声化母音を**除外**し、除外件数を報告する。撥音の後続環境層別と合わせ、分析対象がどれだけ残るかを事前見積もりする（`src/evaluate/estimate_rq3_sample.py`）。
  - RQ4 — jsut-label・Julius はいずれも無声化を扱わない。MFAだけが無声化音素を持つ点は撥音と同方向の構造的差異。ただしMFAの主たる扱いが削除である点は、Juliusの正準音素列固定と対比できる。
  - RQ5 — 無声化母音は「境界が原理的に決まらないため手修正しても精度が上がらない」クラスとして現れる可能性。**修正の費用対効果が最も悪い領域**として示せれば実務的価値が高い。

### `mapping/mfa_phone_class.tsv` の新設（2026-07-20）

- **新設理由**: 本表は**コーパス間の対応表ではなく、MFA音素そのものの内部分類表**である。
  `csj_mfa_map.tsv` / `jsut_mfa_map.tsv` が「CSJ/jsut-labelのラベル ↔ MFA音素」の対応を担うのに対し、
  本表は「MFA音素 → RQ1の音素クラス」の割り当てのみを担う。MFA音素は既に正規形であり、
  MFA出力を中間表現に変換する際に必要なのは対応付けではなくクラス割り当てだけであるため、
  既存2表には収まらない。
- **収録範囲**: japanese_mfa v3.0.0 辞書の**全84音素**（過不足なく網羅していることを検証済み）。
  jsut-labelには対応物が存在しない音素（無声化高母音 `i̥`/`ɨ̥`/`ɯ̥`、`ʔ`、`spn`）を含むため、
  `jsut_mfa_map.tsv` では代替できない。
- **分類は既決事項に従う**: 長母音/短母音を別クラス、促音を破裂音/摩擦音/破擦音で別クラス、
  撥音の異音は `moraic_nasal` に統合（後続環境の層別は変換器側）、無声化高母音は
  `devoiced_high` として独立、`ʔ`・`spn` は `non_phonemic` としてRQ1の誤差解剖から除外。
- **⚠ 計画書のRQ1音素クラス設計に無いクラスを4つ追加した（要確認）**: 実インベントリを
  網羅するには、計画書が列挙するクラス（短母音・長母音・促音・撥音・無声化母音・破裂音・
  摩擦音・破擦音・弾き音）だけでは不足する。次の4クラスを暫定で追加し、表中に ⚠ を付けた。
  - `nasal`（オンセット鼻音 `m` `n` `ɲ` `mʲ`）
  - `approximant`（`j` `w`）
  - `geminate_flap`（`ɾː` `ɾʲː`、計48件）
  - `geminate_approximant`（`wː`、1件）
- **⚠ 記号衝突**: `m` / `n` / `ɲ` / `mʲ` は撥音の異音としても実現されるが、オンセット子音と
  記号が同一で静的に判別できない。本表では `nasal` に分類し、撥音かどうかの判定は
  `src/evaluate/sequence_align.py` がMFA単語層から辞書エントリを辿って行う
  （「撥音の異音統合」問題2を参照）。
